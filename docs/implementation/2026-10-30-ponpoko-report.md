# 너구리 게임 구현 결과

작성일: 2026-10-30 (Asia/Seoul)

## 구현 범위

ASP.NET Core MVC / Razor / C# net10.0 서버와 Babylon.js 9.33.1 / JavaScript 클라이언트로 1인용 게임을 구현했습니다. 외부 CDN 없이 로컬 번들을 제공하며, Node.js는 빌드와 검증에만 사용합니다.

- 이동·점프·사다리·단방향 발판·낙하 판정.
- 먹거리·적 순찰·가시·보너스/뱀 항아리.
- 점수·목숨·제한 시간·재도전·3개 스테이지·최종 클리어.
- 고정 60Hz 시뮬레이션과 독립 렌더링.
- 키보드와 화면 버튼, 일시정지·창 이탈·재시작·음소거.
- 자체 도트 그래픽과 Web Audio 효과음.
- IIS용 게시 스크립트와 배포·복구 안내.

원작의 전체 맵·수치·그래픽을 그대로 복원한 버전은 아닙니다. 계정, DB, 멀티플레이와 터치 조작은 포함하지 않습니다.

## 최종 검증

| 검증 | 결과 |
|---|---|
| Node 단위 테스트 | 32/32 통과 |
| Chromium 브라우저 테스트 | 7/7 통과 |
| 게시 결과물 브라우저 검증 | 2/2 통과 |
| Release 빌드 | 경고 0 / 오류 0 |
| 실제 키 입력으로 3개 맵 완주 | 통과, 남은 목숨 3 |
| 실제 IIS 서버 | 서버 정보 미제공으로 미검증 |

브라우저 검증에는 실제 키 입력에 의한 득점·완주, 일시정지·재시작, 화면 비율, WebGL 실패와 BFCache 수명주기 이벤트 회귀 테스트가 포함됩니다. BFCache 테스트는 persisted 페이지 이벤트를 발생시켜 복귀 후 재개와 단일 RAF, 정상 종료 시 해제를 확인하며, 실제 브라우저 이력 캐시 채택 여부까지 강제하는 테스트는 아닙니다.

사망·시간 초과·항아리 등 수치 규칙은 단위 테스트로 검증했습니다. 세 맵의 캡처를 시각적으로 확인했습니다. 사람이 직접 수행한 QA와 자동 검증을 동일하게 주장하지 않습니다.

게시 검증은 Production Kestrel을 **artifacts/publish를 기준 경로로** 실행합니다. /ponpoko/의 페이지·번들·게임 시작, 외부 CDN 요청 부재, 소스 체크아웃 전용 파일이 404인지 확인했습니다.

## 독립 리뷰

새 컨텍스트의 gpt-6-astra 리뷰 결과: Critical 0 / Important 1 / Minor 0.

중요 발견 사항은 pagehide에서 캐시 보존 여부와 관계없이 앱을 정리하여 BFCache 복귀 시 게임과 버튼이 멈추는 문제였습니다. cached_page_restore_keeps_single_live_game 테스트의 실패를 확인한 뒤 수정했고, 전체 41개 테스트와 Release 빌드 및 갱신한 게시 결과를 검증했습니다.

캐시 보존 시에는 일시정지하고 상태와 이벤트를 보존합니다. pageshow 복귀 시 크기와 시계를 다시 맞추며 사용자가 재개할 때까지 멈춥니다. 실제 페이지 종료일 때만 앱을 해제합니다.

보류한 경미한 리뷰 사항: 없음. 두 번째 리뷰 대신 회귀 테스트와 전체 테스트로 수정 결과를 확인했습니다.

## 실행과 배포

개발 실행은 [README](../../README.md), 서버 배포와 복구는 [IIS 안내](../deployment/iis.md)를 참조합니다.

```powershell
npm ci
npm run build
dotnet run --project RaccoonGame.csproj --no-launch-profile --urls http://localhost:5080
```

```powershell
powershell -NoProfile -File scripts/publish.ps1
```

IIS 운영 서버의 설치·설정·서비스·인증서는 변경하지 않았습니다. 원격 저장소로 push하거나 main에 병합하지 않았습니다. 앱이 관리하는 워크트리에 커밋을 보존합니다.

## 실행 중 판단 기록

다음은 실행 원장의 Ruling 항목 전체를 순서대로 보존한 것입니다. 각 항목은 이유와 판단이 틀렸을 때의 비용을 포함합니다.
- Ruling: 사용자의 executing-plans 호출을 제시한 계획과 첫 버전 범위의 실행 승인으로 해석한다 — 문서를 제시하고 실행 방법을 물은 뒤 사용자가 직접 실행 스킬을 선택했음 — 틀리면 게임 수치와 범위를 수정해야 함.
- Task 5: Ruling: 전체 맵의 사다리·적 시각 검토는 Task 7의 실제 세 맵으로 검증한다 — 현재 첫 맵은 계획대로 바닥과 음식 하나뿐임 — 틀리면 시각 문제 발견이 후반으로 늦어짐.
- Task 7: Ruling: 브라우저 완주에서는 사다리를 1초 누르고 마지막 음식 접근에 50ms 여유를 둔다 — RAF 콜백 간격 때문에 정확한 모델 틱 수를 ms로 바꾼 입력이 한 틱 짧아질 수 있음 — 틀리면 브라우저 입력 경계 오차를 가릴 수 있어 정확한 틱 판정은 단위 테스트로 유지.
- Task 8: Ruling: 게시 smoke의 cwd를 artifacts/publish로 고정하고 DLL 상대 경로를 변경한다 — 계획의 루트 cwd 실행은 게시 DLL이 소스 wwwroot를 읽게 하여 실제 게시 검증을 약화함(소스 전용 sentinel 200 재현) — 틀리면 배포 환경과 로컬 검증의 경로 해석이 달라질 수 있음.
- Final: Ruling: 실제 IIS 모듈·앱 풀·인증서 검증은 배포 대상 정보가 없으므로 현 범위에서 제외한다 — 이번 작업은 게시 준비와 로컬 검증이며 서버 조작은 요청되지 않음 — 틀리면 IIS 고유의 환경 문제를 출시 전에 놓칠 수 있음.
- Final: Ruling: 원작의 정확한 수치·맵 일치는 이번 세 스테이지의 완료 기준에 넣지 않는다 — 원작 참고의 자체 수치 버전으로 계획을 실행했음 — 틀리면 원작과 조작감·난이도 차이가 남음.
