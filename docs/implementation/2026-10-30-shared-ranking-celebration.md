# 공유 순위와 클리어 연출 변경 기록

## 변경
- 게임 오버/20스테이지 완주 뒤 이름 입력, 최종 점수와 전체 순위, 공유 TOP 10을 표시한다.
- Microsoft.Data.Sqlite 10.0.14로 서버 파일에 저장한다. 기본 App_Data/leaderboard.db, 구성 키 Leaderboard:DatabasePath로 변경 가능하며 웹 정적 파일 경로에 포함하지 않는다.
- 공동 순위(1,1,3), 매개변수 SQL, CSRF·이름·점수 검증, 동일 판의 멱등 제출, 저장 오류 재시도와 늦은 응답 무시를 적용했다.
- 스테이지 종료 시 획득 점수·시간 보너스·총점과 5마리 너구리의 춤을 5초 동안 표시한다. 직접 만든 약 4.6초 복고풍 선율을 재생한다.
- 과일 표시의 DOM 순서는 유지하고 화면 배치는 오른쪽부터 왼쪽으로 누적한다. 기존 점수·20스테이지·3번 기회와 이동 판정은 유지한다.

## 구현 판단
사용자가 IIS 공유를 선택한 뒤 별도 DB 서버가 필요 없는 SQLite를 구현자가 선택했다. 기본 경로는 편리한 개발용 설정이고, 운영에서는 배포 버전 폴더 밖의 영구 데이터 경로와 앱 풀 수정 권한이 필요하다. 단일 서버 기준이며 여러 서버로 확장하면 DB 구성을 다시 선택해야 한다.

클리어 연출은 원작의 점수·너구리 춤·음악이라는 요청의 구성을 반영한 자체 표현이다. 원작 음원이나 정확한 프레임·악보를 재현했다고 주장하지 않는다. 점수는 브라우저 보고값이며 서버 플레이 검증은 별도 기능이다.

## 검증 기록
- RED: 클리어 점수 요약 부재, 긴 음악 부재, 제출 토큰/결과 흐름 부재를 먼저 확인했다.
- Node 단위 테스트 51개 통과: 전체 20스테이지 경로, 점수·목숨·낮은 점프, 5초 연출과 점수 요약, 음악과 정리 동작.
- 브라우저 테스트 13개 통과: 실제 키보드 클리어, 5마리 춤, 오른쪽 과일 배치, 이름 저장·순위·동점·동시 제출·상위 10명 밖 본인 순위·응답 유실 후 재시도와 중복 방지.
- 게시 테스트 3개 통과: /ponpoko/ 하위 경로와 리소스, 소스 체크아웃 파일 비노출, 동일 DB로 서버 프로세스를 재시작한 뒤 기록 유지, 저장 경로 장애의 503과 정상 게임 페이지.
- dotnet build 경고 0/오류 0, Release publish 성공, git diff --check 통과.
- 캡처 artifacts/stage-clear-dance.png와 artifacts/shared-ranking.png를 시각적으로 확인했다.
- 독립 최종 검토에서 UUID 메서드 부재 시 시작 실패와 늦은 GET 실패의 성공 안내 덮어쓰기를 발견했다. 각각 브라우저 RED를 확인한 뒤 getRandomValues UUID 대안과 saved 응답 가드를 적용했고 전체 npm test에서 GREEN을 확인했다.
- 기본 지원을 벗어난 원작 선율 정확성·실제 IIS 권한/배포·부정 점수 방지·여러 서버 운영·대규모 부하는 검증하지 않았다.

실제 IIS 실서버 배포는 수행하지 않았다. 데이터 경로·앱 풀 권한·재배포 및 백업 절차는 docs/deployment/iis.md에 기록했다.
