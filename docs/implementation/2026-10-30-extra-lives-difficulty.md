# 추가 목숨과 후반 난이도 변경 기록

## 변경
- 누적 점수 30,000점마다 목숨 +1. 점수 주머니와 시간 보너스를 포함하고, 한 번에 여러 기준을 넘어도 모두 지급한다.
- 지급 기준 이력은 같은 판의 피격/재시도에서 유지하고 새 게임에서 초기화한다. 기존 체크포인트 점수 복구로 같은 기준을 반복 통과해도 중복 보너스를 지급하지 않는다.
- 하단 목숨 아이콘은 3개를 넘어도 실제 개수만큼 추가하고 좁은 화면에서는 줄바꿈한다. 조작 안내에 30,000점 보너스를 표시했다.
- 송곳은 2스테이지마다 추가해 총 0→9개로 증가한다.
- 5스테이지부터 최상단에 폭 64~88의 틈, 9스테이지부터 바로 아래층에도 넓은 틈을 배치했다. 낮은 점프 수치는 유지하고 아래 두 층과 내부 사다리로 우회한다.
- 중앙 사다리를 보강해 넓어진 순찰 구간에서 적을 피해 층을 바꿀 수 있다.
- 애벌레 순찰 폭은 68에서 220으로 증가한다. 뱀은 초반 폭 64에서 후반 최대 276까지 커지며 각 적은 자신이 있는 연결 발판의 범위를 벗어나지 않는다. 느린 뱀 속도는 6으로 유지한다.

| 스테이지 | 송곳 | 사다리 | 주 애벌레 순찰 폭 |
|---|---:|---:|---:|
| 1 | 0 | 6 | 68 |
| 5 | 2 | 13 | 100 |
| 9 | 4 | 13 | 132 |
| 13 | 6 | 13 | 164 |
| 17 | 8 | 13 | 196 |
| 20 | 9 | 13 | 220 |

## 검증
- RED 확인: 30,000점 경계/다중 지급/중복 지급 방지, 늘어나는 송곳과 실제로 넘을 수 없는 틈, 뱀의 점진적 순찰 범위. 기존 고정 HUD는 [3,3,3,3,3]으로 실패했다.
- GREEN: 단위 58/58, 브라우저 14/14, 게시 3/3로 총 75개 통과.
- 실제 모델 입력 경로로 20스테이지를 각각 완주하고 한 게임으로도 연속 완주했다. 연속 검증 결과 231,840점, 지급 7회, 남은 목숨 10개.
- HUD는 [3,4,5,4,3]을 확인했다. 이전 최고점·일시정지에서 오지급하지 않으며 새 게임은 다시 지급할 수 있다.
- 송곳 개수는 단계에 따라 줄지 않으며, 음식·주머니·송곳의 발판 지지와 사다리/먹거리 입구 안전을 확인했다.
- Release build 경고 0/오류 0, publish 및 /ponpoko/ 하위 경로·공유 DB 재시작 유지·장애 처리 검증 통과.
- 독립 최종 코드 검토에서 수정할 결함 없음. 검토자가 별도로 관련 테스트 12/12 통과를 확인했다.
- 실제 Babylon.js 렌더러에 제어된 20스테이지 상태를 넣어 데스크톱과 480px 화면을 캡처했다. 송곳 9개와 목숨 10개를 표시했고 목숨 영역 넘침 및 페이지 오류가 없었다. 캡처: artifacts/difficulty-stage20.png, artifacts/difficulty-stage20-mobile.png.
- 실제 사람의 체감 난이도와 IIS 실서버 배포는 검증하지 않았다.

## 경로 자료 재생성
테스트용 탐색 도구 tests/helpers/solve-levels.mjs가 실제 이동/충돌 함수를 이용해 경로를 제안한다. node tests/helpers/solve-levels.mjs 또는 뒤에 스테이지 번호를 지정해 실행한다. 기존 경로가 여전히 유효하면 유지한다. 결과는 tests/fixtures/solutions.js이고, npm run test:unit으로 실제 GameModel 재생을 확인한다. 프로덕션 디버그 버튼이나 검증용 훅을 추가하지 않았다.
