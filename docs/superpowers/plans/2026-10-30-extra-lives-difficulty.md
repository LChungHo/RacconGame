# 추가 목숨과 후반 난이도 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. 기존 직접 구현 방식을 유지한다.

**Goal:** 매 30,000점의 추가 목숨과 점진적인 송곳·우회 경로·적 순찰 범위를 제공한다.
**Architecture:** 점수 처리에서 지급 기준을 기록하며 목숨 HUD를 동적으로 늘린다. 스테이지 데이터에 난이도를 반영하고 실제 입력 경로를 재생해 모든 맵의 완주를 검증한다.
**Tech Stack:** 기존 ASP.NET Core MVC, Babylon.js, JavaScript.
**Spec:** docs/superpowers/specs/2026-10-30-extra-lives-difficulty-design.md · 최신 사용자 요청. 30,000·60,000·90,000점 등마다 +1. 후반 송곳 증가, 점프로 건너지 못하는 길을 다른 경로로 우회, 적 이동 영역 확대.

## 구현 결정
같은 판의 각 점수 기준은 한 번만 지급한다. 실패 후 현재 판 점수가 체크포인트로 돌아가는 기존 규칙 때문에 재통과한 기준을 중복 지급하면 무한 목숨 획득이 가능하기 때문이다. 새 게임은 지급 이력도 초기화한다. 시간 보너스도 누적 점수에 포함한다.
송곳은 두 스테이지마다 추가하며, 5스테이지부터 위층에 넓은 틈과 우회 사다리를 배치한다. 9스테이지부터 아래 위층에도 넓은 틈을 추가한다. 아래 두 층은 이동 경로를 보존한다. 뱀은 느린 속도를 유지하며 순찰 범위만 확대한다. 적은 자신이 있는 연결된 발판 범위 안에서 순찰한다.

## Global Constraints
- 20스테이지 과일 순서·물음표 4개와 고정 결과·낮은 점프·공유 순위·클리어 연출을 유지한다.
- 목숨 개수에 임의 상한을 추가하지 않는다.
- 무작위 맵 생성이나 운영 IIS 변경은 하지 않는다.

## Review Focus
- 한 번에 여러 지급 기준을 넘어도 빠짐없이 지급한다.
- 피격·재시작·일시정지·이전 최고점으로 중복 지급하지 않는다.
- 추가 목숨이 3개를 넘어도 HUD 표시와 실제 생존 횟수가 일치한다.
- 음식·주머니·사다리가 틈이나 송곳과 겹쳐 진행을 막지 않는다.
- 넓은 틈과 확대된 적 범위가 있어도 모든 스테이지를 실제 입력으로 완주할 수 있다.
