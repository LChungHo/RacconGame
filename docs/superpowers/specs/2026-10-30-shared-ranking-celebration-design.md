# 공유 순위와 클리어 연출 설계

## 사용자 확정 요구
- 게임 종료 후 이름을 입력하고 최종 점수와 전체 순위를 표시한다.
- 기록은 IIS 서버에 저장해 모든 플레이어가 공유한다.
- 스테이지 클리어 후 점수와 여러 너구리의 춤, 음악을 표시한다.
- 진행한 스테이지의 과일은 오른쪽에서 왼쪽으로 누적한다.
- 기존 ASP.NET Core MVC, Babylon.js, JavaScript, IIS 구성과 20스테이지 규칙을 유지한다.

## 대안과 구현자 결정
브라우저별 저장과 서버 공유 중 사용자가 서버 공유를 선택했다. 서버 저장 구현은 SQLite를 선택했다. JSON 파일보다 동시 기록과 원자적 중복 제출 처리가 명확하며, SQL Server보다 별도 운영 구성이 작다. 이 선택은 단일 IIS 서버의 로컬 디스크를 전제로 한다.

이름은 공백 제거 후 1~12자이고, 동점은 공동 순위(1,1,3)이다. 상위 10명과 별도의 본인 순위를 표시한다. 판별 ID는 한 판 동안 유지해 저장 응답이 유실된 뒤 다시 제출해도 같은 기록을 반환한다. DB는 공개 wwwroot 밖에 두고 구성으로 영구 경로를 바꿀 수 있다. 실제 IIS 설정 및 배포는 이번 변경 범위에 없다.

클리어는 시뮬레이션 시간 5초 동안 표시한다. 획득 점수(먹거리와 점수 주머니), 시간 보너스와 누적 총점을 구분하고, 기존 너구리 도트 5마리가 번갈아 움직인다. 음악은 직접 만든 약 4.6초 복고풍 선율이다. 원작 음원을 확보하거나 정확한 원작 연출을 검증한 것으로 설명하지 않는다. 일시정지는 클리어 시간과 춤 진행을 멈추고 오디오를 정리한다.

## 경계와 실패 처리
Controller는 HTTP와 검증을, SQLite 서비스는 트랜잭션·조회·저장을, 결과 모듈은 이름 입력과 취소 가능한 네트워크 상태를 담당한다. SQL 매개변수, CSRF 토큰과 DOM textContent를 사용한다. 재시작과 정리 시 요청을 취소하고 세대가 다른 응답을 무시한다. DB 장애는 503과 재시도 안내로 표시하며 게임 페이지와 플레이를 막지 않는다.

점수는 클라이언트가 계산해 제출한다. 서버에서 플레이를 재실행하는 부정행위 방지, 계정, 여러 서버 사이의 분산 DB는 이번 범위에 포함하지 않는다.
